# Phase 4: PDF・Office文書の本文抽出

## 目的

Phase 3の制限付きファイル取得を再利用し、設定済みSharePointサイト内のPDF・DOCX・XLSX・PPTXから、検索・要約に利用できるプレーンテキストを読み取り専用で抽出する。

## MCPツール

### `sharepoint_extract_document_text`

入力されたファイルURLを検証・ダウンロードし、形式ごとの抽出器へ渡す。

- 入力: 設定サイト内のPDF・DOCX・XLSX・PPTX URL
- 出力: ファイルメタデータ、形式、単位種別、単位数、本文、文字数、切り詰め有無
- 本文は最大100,000文字
- バイナリ本体はツール結果へ含めない

## 形式別の処理

### PDF

Mozilla PDF.jsでページごとのテキスト項目を取得する。

- 最大200ページ
- XFA、WebAssembly、フォント描画を無効化
- 文書アクションや添付ファイルを実行・展開しない
- ページ単位の見出しを付加

### DOCX

Open XML ZIPから次のXMLだけを抽出する。

- `word/document.xml`
- ヘッダー、フッター
- 脚注、文末脚注

削除済みテキストとフィールド命令を除外し、段落、改行、タブをプレーンテキストへ変換する。

### XLSX

ワークブック、リレーション、共有文字列、ワークシートXMLだけを抽出する。

- シート名を保持
- セル参照と保存済みセル値を返却
- 共有文字列、インライン文字列、真偽値、エラー、数値に対応
- 最大20,000個の非空セル
- 数式を再計算せず、ファイルに保存された結果値を使用

### PPTX

スライドXMLとスピーカーノートXMLだけを抽出する。

- 最大200スライド
- スライド番号とノート番号を付加
- 画像、埋め込みオブジェクト、動画、マクロを展開しない

## ZIP展開のセキュリティ境界

- MCP resourceとして直接返す場合はPhase 3の5 MiB上限を適用
- 文書解析だけに使うPDF・Officeファイルは20 MiBまで許可し、元バイナリはMCP応答へ含めない
- 最大1,000 ZIPエントリ
- 対象XML 1部品あたり最大2 MiB
- 対象XMLの展開後合計は最大8 MiB
- 展開前の宣言サイズと展開後の実サイズを両方検証
- 絶対パス、バックスラッシュ、NULL、`..`を含むZIPパスを拒否
- 必要なXML部品だけを展開
- `DOCTYPE`と`ENTITY`宣言を拒否

## 共通セキュリティ境界

- SharePointへの要求はGETだけを使用する。
- URL、拡張子、サイズ、SharePoint応答パスをPhase 3と同じ境界で検証する。
- 文書内のスクリプト、マクロ、外部リンク、埋め込みオブジェクトを実行しない。
- 抽出本文をログへ記録しない。
- ファイルや抽出本文をローカルへ自動保存しない。
- 抽出本文は最大100,000文字で切り詰める。

## 制限事項

- スキャンPDFや画像内文字のOCRは行わない。
- DOC、XLS、PPTなどの旧バイナリOffice形式は未対応。
- パスワード保護・暗号化文書は未対応。
- Excelの表示書式、日付変換、数式再計算、グラフ、ピボットは未対応。
- Wordの図形、テキストボックス、変更履歴の完全な再現は保証しない。
- PowerPointの視覚的な配置、図、SmartArt、アニメーションは抽出しない。
- 抽出順序はファイル内部のXML順であり、画面上の読み順と異なる場合がある。

Phase 6で、文書全体を返さずページ・見出し・シート・スライド単位で探索するアウトライン、文書内検索、選択ノード本文取得を追加した。詳細は[`phase-6-document-structure.md`](phase-6-document-structure.md)を参照。
