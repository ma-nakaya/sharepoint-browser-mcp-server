# Phase 9: 大きい文書の段階的解析

## 背景

SharePoint検索では、本文説明に必要なPowerPointやPDFが5 MiBを超える場合がある。従来はrawファイル取得と文書解析が同じ5 MiB上限を共有していたため、文書内検索やスライド単位取得へ進む前に拒否されていた。

## 分離した上限

- `sharepoint_download_file`: 最大5 MiB。MCPの埋め込みresourceとしてバイナリを返す。
- 文書抽出・アウトライン・文書内検索・選択ノード取得: 解析元ファイルを最大20 MiBまで許可する。
- 解析元バイナリはMCP応答へ含めず、抽出したテキストとメタデータだけを返す。

文書解析から任意の上限を指定することはできない。内部コードが固定の20 MiB上限を指定し、トランスポートも20 MiBを超える値を拒否する。

## 展開後の安全境界

ファイル上限を拡張しても、Office ZIPの展開境界は変更しない。

- 最大1,000 ZIPエントリ
- 対象XML 1部品あたり最大2 MiB
- 対象XMLの展開後合計は最大8 MiB
- 最大200ページ・シート・スライド
- 抽出本文は最大100,000文字
- 必要なXML部品だけを展開
- `DOCTYPE`と`ENTITY`を拒否
- マクロ、外部リンク、埋め込みオブジェクト、画像、動画を実行・展開しない

画像を多く含むPowerPointの圧縮済みサイズが大きくても、スライド本文とスピーカーノートのXMLだけを安全境界内で抽出できる。

## 推奨フロー

大きい文書では全文抽出より段階的な取得を優先する。

1. `sharepoint_search`で対象文書を特定する。
2. `sharepoint_search_document`で質問に関係するページ・シート・スライドを検索する。
3. 返されたノードIDを`sharepoint_get_document_nodes`へ渡す。
4. 必要な部分だけを根拠として回答する。
